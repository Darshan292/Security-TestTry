## 1. Verdict

**The gateway is not secure enough for real HRIS data, and it is not enterprise-ready.**
It fails its own pre-registered headline gate on held-out data:

| Gate (EVALUATION_PLAN.md) | Target | DEV | **TEST** |
|---|---|---:|---:|
| Character leak rate on sensitive spans | ≤ 1.0 % | 2.11 % | **2.56 %** |
| Documents sending ≥ 1 raw sensitive value to the provider | (no gate set) | 9.5 % (377/3,977) | **14.6 % (181/1,240)** |
| HIGH-risk types recall ≥ 0.98 | all pass | all pass | **AADHAAR 0.918, SECRET 0.916 FAIL** |
| Leak under the worst adversarial transform | (no gate set) | 45.5 % | **38.0 %** |
| E-UTIL output quality | ≤ 5 % degradation | **not run** | **not run** |

What it *is*: a working, tested pipeline that removes most structured identifiers
and all roster-known employee names from synthetic HR text. It is suitable for a
**synthetic-data pilot only**.

## 2. Method, and how far to trust these numbers

- Gold data was generated by an agent that never saw the detector code. Spans are
  computed by construction. Gates were frozen before any run.
- Detectors were tuned on **DEV** (and the tune split). **TEST was evaluated exactly once**,
  enforced by a lock file tied to a clean commit.
- **Contamination disclosures**
  1. While tuning, the detector agent printed `MANIFEST.json`, which lists test *template
     names* (not test text). It reports that it did not tune toward them.
  2. After the test run, test failures were analysed (read-only) for this report.
     Any fix informed by that analysis means **the next release needs a freshly generated
     test split** (new seed and new templates). This test split is now spent.
- **Synthetic only.** The corpus has about 6 hr_free_text templates per split. Real HR text
  is more varied, so these numbers are an **upper bound** on real-world recall (RISK_REGISTER R-03).
- The lock file recorded an empty corpus hash because of a key-matching bug in the runner.
  The test file's hash was re-verified against the manifest by hand after the run (matching).

## 4. What the TEST run proved

1. **The DEV scores of 1.000 did not generalise.** Rule-based detection is as good as its
   coverage of field names and phrasings. TEST templates introduced shapes DEV never had:
   - `"nationalId": "275790399234"` in UKG JSON (Aadhaar under an unseen key)
   - Aadhaar in a TSV column far from any keyword
   - `postgresql://hrms:summer_4298#@10.0.4.12` (a credential inside a connection URL)
   
   All of these leaked.
2. **Exact-data matching against the roster is the strongest control measured.** 100 % recall on
   5,766 roster-name spans across both splits (DEV 4,446 + TEST 1,320). For HRIS, where most names are employees,
   this is the lever the review's "PERSON ≥ 0.90 is not enough" comment was pointing at.
3. **The egress invariant caught nothing real, and it produced false alarms.** Measured after the run
   by replaying `protect()` + `egress.check()` over both splits with the frozen code:
   **0 true catches** while 181 TEST documents leaked (it only knows *detected* values, T20), and
   **8 false alarms** on TEST (0.6 % of items would be blocked). Two bugs combine here. The TSV field-context
   detector labels header cells ("Date", "IFSC") as values, and the sweep then finds those words
   *inside our own alias tokens* (`[date_of_birth_…]`). It is a bug detector, not a recall control,
   and it currently has an availability bug of its own (W9).
4. **Output-gate defence in depth partly works.** In non-streaming mode the gate
   masked the raw Aadhaar that input detection missed. But the provider had already
   received it, and in streaming mode the gate missed it (W4).

## 5. Biggest remaining security weaknesses (ranked)

| # | Weakness | Evidence | Severity | Proposed fix (NOT implemented; awaiting review) |
|---|---|---|---|---|
| W1 | **Names outside the roster in free text** are the dominant leak | 1.96 % of TEST chars; 1,160/1,160 DEV PERSON misses are external names | High | Phase 2 NER (GLiNER, Apache-licensed checkpoint), measured on a fresh split. No more regex cues: they already over-mask policy titles. |
| W2 | **Evasion**: spaced letters, obfuscated emails, case, NBSP | TEST leak 38 % / 14 % / 5.6 % / 5.6 % | High | D0: collapse single-letter runs, de-obfuscate `[at]`/`[dot]`, and allow digit groups separated by spaces or NBSP for account numbers. Fail closed where unsure. |
| W3 | **Coverage generalisation** of structured types | AADHAAR 0.918 (unseen `nationalId` key, TSV); SECRET 0.916 (password in `scheme://user:pass@host`) | High (HIGH-risk types) | A URI-credential recognizer; Verhoeff-valid 12-digit numbers in any HRIS-shaped payload escalate to BLOCK or REDACT by policy rather than needing a keyword. Grow the field lexicon from real Workday/UKG schemas, not from the corpus. |
| W4 | **The streaming output gate loses context**: raw PII passes in streams that is masked when non-streamed | 2 TEST items, raw Aadhaar reached the client in streaming mode | Medium–High | Gate context must include the request's detected-value set (Aho-Corasick of known raw values, like the egress sweep) and a larger lookback. ADR-0008's "sliding window" claim is wrong for context-dependent recognizers. |
| W5 | **Minified JSON longer than 256 chars splits aliases** in streaming restore | 26 TEST items (UKG JSON): client receives `[PE` + `RSON_…]` unrestored | Medium (integrity; aliases are pseudonyms) | Cut long runs only at non-alias-prefix boundaries (JSON delimiters `,":{}`). ADR-0008's "impossible by construction" claim is currently false. |
| W6 | **E-UTIL has never run** | No API key in this environment | Unknown | Run `eval/run_util.py` against the target model. Until then, output-quality equivalence is **unmeasured**, which was the review's central criticism. |
| W7 | **Synthetic data only**; few templates per split | Corpus design | Unknown, likely negative | E-DET-R spot check inside a client boundary (EVALUATION_PLAN). |
| W9 | **The egress invariant false-fires on alias text**, and TSV header cells are detected as values | 8/1,240 TEST requests would fail closed | Medium (availability) | Sweep only text outside alias tokens; add a TSV header-row guard. Re-verify on a fresh split. |
| W8 | Precision on unseen templates | 66 % of TEST negatives flagged | Utility | Remove the preposition cue once NER exists; add a negative context for ticket ids. |

Also out of scope for this slice, and therefore **not evaluated**: pen testing, key management
(the master key is an environment variable, no KMS), policy-pack signing, per-tenant
roster isolation (one shared roster key), provider contracts, and end-to-end latency under load.

## 6. Design corrections this evaluation forces

| ADR | Claim | Reality | Action |
|---|---|---|---|
| ADR-0002 | Alias suffix is 30-bit Crockford-32 | Letters-only suffixes matched ordinary identifiers (`Phone_Number`), and the gate rewrote them in 166/3,977 DEV items. **Fixed in `a51c22d`**: the suffix now starts with a digit and uses Crockford letters (~28.3 bits). | Amend ADR-0002 (collision rate at 200 entities ≈ 6×10⁻⁵, still detectable). |
| ADR-0008 | Split-placeholder leaks impossible by construction; D2 gate on a sliding window | False for runs over 256 chars (W5) and for context-dependent recognizers (W4) | Amend after fix. |
| ADR-0005 | D0 handles spaced/homoglyph forms "partly" | Spaced leak 38 %: in practice "not handled" | Restate as a measured residual. |
| DESIGN §5.2 | PERSON primarily via EDM + NER | EDM measured at 1.000 on roster names | Keep. Make roster sync (F-11) a Phase 1 prerequisite, not Phase 4. |

## 7. Does the architecture match the enterprise patterns in `research/`?

The table uses the provenance classes from INDUSTRY_PATTERNS.md and VERIFICATION_2026-09-30.md:
**P** = primary vendor source, **S** = secondary.

| Industry pattern (source) | Our architecture | Match? | Measured? |
|---|---|---|---|
| Masking in a gateway between app and LLM (Salesforce S, Uber S, SAP P, Cloudflare P) | OpenAI-compatible gateway, sole holder of provider keys | **Yes** | Gateway tests: 30 end-to-end, asserting on what the mock provider received |
| Hybrid detection: regex/checksum/context + ML (Salesforce S, AWS S, Presidio) | Regex/checksum/context/field-name + roster EDM; **no ML yet** | **Partial**: the ML half is missing, and W1 is exactly that gap | Yes (this report) |
| Reversible placeholders with a server-side map (Salesforce, SAP pseudonymisation P, Uber S) | Scoped HMAC aliases, map rebuilt per request, nothing at rest | **Yes, stronger**: consistent across turns without state, which Uber reported as a problem (S) | Round trip 1,213/1,240 TEST |
| Consistent placeholders across turns (Uber lesson, S) | Deterministic per conversation scope | **Yes** | Unit tests; not measured with a real LLM |
| Streaming: vendors either buffer everything (Cloudflare DLP P, Guardrails P) or re-chunk tags (SAP P) | Bounded hold-back, gate before restore | **Different, more ambitious; currently buggy** (W4, W5) | Yes: this is where TEST found defects |
| Tool-call args/results covered (SAP P for pseudonymisation; Cloudflare P as text; AWS: not by default) | Tool results are input; args buffered whole, gated, restored | **Yes** | Gateway tests only |
| Audit trail (Salesforce stores original + masked prompts, S) | Content-free egress ledger (hashes, counts, versions) | **Deliberately different**: no prompt content at rest | Unit/gateway tests |
| Detect/flag/block DLP (Cloudflare P, Purview S) | BLOCK for HIGH types by policy; purpose-bound decision tables | **Yes, and adds purpose binding** (none of the surveyed vendors documents this) | Unit tests |
| Vendors state no accuracy guarantee and publish no latency (SAP P, Salesforce S) | Per-type recall with confidence intervals and a leak rate, plus latency, published here | **Exceeds the norm on transparency** | Yes |
| Masking costs output quality (Salesforce disables it for agents, S; Uber, S) | E-UTIL designed | **Unverified**: not run (W6) | **No** |

**Net assessment.** Structurally the architecture matches, and in three places goes beyond,
what the surveyed vendors document: stateless scoped aliases, purpose binding, and a
content-free audit trail. The gaps are not architectural. They are in the **detection
layer** (no ML, and brittle to evasion and unseen templates), in the **streaming
implementation** (the two bugs above), and in **evidence** (no utility or real-data measurement). The
biggest mismatch with industry practice is the missing ML detector, which every
surveyed vendor with name detection uses. Those claims are secondary sources for
Salesforce and AWS.
