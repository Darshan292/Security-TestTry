## Corrections (claims found wrong or needing rewording)
1. INDUSTRY Cloudflare row: "UNVERIFIED (docs issue #28325)" for tool-call/streaming conflates two features. DLP: buffers full response when response scanning is on; request-only DLP does not buffer. Guardrails (a different feature): REST endpoints do not enforce on streamed responses at all; gateway endpoints buffer and de-stream. Also DLP DOES scan tool-call args/results, but only as plain text within the JSON body.
2. Anything implying Cloudflare could "mask" is not supported: actions are pass/flag/block only (agrees with the existing note, now primary-sourced).
3. SAP "Optional module ... Pseudonymization yes; anonymization no" is right for reversibility, but note the streaming caveat: the tag re-chunking shifts chunk sizes, and unmasking works on streamed output only for pseudonymization. Also the only listed provider is "SAP Data Privacy Integration - Anonymization" with 27 entities of limited locale.
4. OSS knowledgator "license UNVERIFIED" can now be Apache-2.0 (base seen; others by family statement).
5. Purview/Content Safety: do not describe as PII masking of prompts. Nothing found supports masking.
6. Presidio: no native async engine; use to_thread/executor. Recommend removing "True async: UNVERIFIED" in favor of "no native async found".
